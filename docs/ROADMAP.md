## 장기 비전: 일회성 이전 도구 → 계속 쓰는 동기화 앱

목표: 데스크톱 로컬 앱이 주기적으로 양쪽 보관함을 비교해, 한쪽에서 좋아요/저장/구독한 것을 반대쪽에도 반영한다.

**왜:** 조사해 보니(2026-10-13) Soundiiz/TuneMyMusic은 유료 플랜에서 주로 플레이리스트를 동기화하고, GitHub 오픈소스는 모두 한 방향 일회성 복사였다. **양방향 + 예약 실행 + 로컬(계정 정보가 PC 밖으로 나가지 않음) + 애매한 매칭은 사람이 검토**하는 조합은 비어 있다.

**지금 구조에서 재사용할 것:** 양쪽 보관함 스냅샷과 변경 감지(`items.first_seen`, `removed`), 매칭 엔진, 검토 화면, 이미 있는 곡 재저장 방지.

**v0.4 설계 메모**

| 문제 | 방향 |
|---|---|
| 무한 반복(핑퐁): A→B로 넣은 곡을 다음 실행에서 B의 새 곡으로 보고 A로 되돌려 보냄 | **짝 테이블**(YTM id ↔ Spotify uri)로 이미 연결된 항목은 건너뜀 |
