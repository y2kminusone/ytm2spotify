# M0 Spike 결과 리포트

> 완료 · 2026-10-12 · 대응: PRD §8

| # | 가정 | 결과 | 비고 |
|---|---|---|---|
| R0 | 사용자가 Spotify 개발자 앱을 만들 수 있다 | ⚠️ 조건부 성공 | 아래 참고 |
| R1 | `PUT /me/library`로 아티스트 팔로우 | ✅ 성공 | 레퍼런스 문서와 달리 artist URI 동작 |
| R2 | PKCE + `127.0.0.1` 리디렉트 인증 | ✅ 성공 | `market=from_token` 함정 있음 |
| R3 | YTM 보관함 전체 페이지네이션 | ✅ 성공 | 차이 235곡은 사용할 수 없는 영상 |
| R4 | 좋아요 곡 videoType 분포 / UGC 매칭률 | ✅ 측정 완료 | UGC 26%, 단순 매칭은 위험 |
| R5 | 검색 limit 10으로 충분 | ✅ limit 확인 / 충분성은 R4와 함께 | 11 이상은 HTTP 400 |

## R0. Spotify 개발자 앱 생성 (새로 발견한 리스크)

- **현상:** Premium 계정인데도 Dashboard에 **Create app 버튼이 표시되지 않는다.** "You haven't created any apps yet" 문구만 보인다. (2026-10-12 확인)
- **우회:** `https://developer.spotify.com/dashboard/create`로 직접 접속하면 앱 생성 폼이 열리고, 생성도 정상 동작한다.
- **참고:** 2026-08 Spotify Community에 같은 증상 보고가 있으나 공식 답변은 없다. 2026-03 이후 Premium 계정당 Development 모드 앱은 1개로 제한된다는 답변도 있다.
- **제품 영향:**
  - 설정 마법사 1단계에 "Premium 필요"를 명시한다.
  - 앱 생성 링크는 Dashboard가 아니라 **`/dashboard/create`로 직접 연결**한다.
  - 문제 해결 가이드에 "버튼이 안 보여요" 항목을 추가한다.
  - 사용자가 이미 다른 앱을 갖고 있으면 새로 만들지 말고 **기존 앱의 Client ID를 재사용**하도록 안내한다(1개 제한). Redirect URI만 추가하면 된다.

## R1. 아티스트 팔로우 (`PUT /me/library`)

- 레퍼런스 문서의 지원 URI 목록에는 `spotify:artist:`가 없지만, 변경 로그는 "Follow Artists → `PUT /me/library` 사용"이라고 안내한다. 실제로는 **동작한다.**
- 테스트(2026-10-12, 대상 NewJeans `spotify:artist:6HvZYsbFfjnjFrWF950C9d`):
  - `GET /me/library/contains` → `[false]`
  - `PUT /me/library?uris=…` (쿼리스트링) → 200
  - `contains` → `[true]`, `GET /me/following` 목록에도 노출
  - `DELETE /me/library?uris=…` → 200, `contains` → `[false]` (원상복구)
- **결론:** 저장과 팔로우 모두 `uris`를 **쿼리스트링**으로 보낸다(최대 40개). 문서와 실제가 다르므로, 통합 테스트로 회귀를 감시할 가치가 있다.

## R2. 인증

- PKCE(Client Secret 없음), Redirect `http://127.0.0.1:8765/callback`, scope 4종(`user-library-read/modify`, `user-follow-read/modify`) 모두 정상이다.
- 읽기: `GET /me/albums`, `GET /me/following?type=artist`, `GET /me/tracks` 정상 (테스트 계정: 앨범 18 / 아티스트 17 / 곡 43).
- **함정:** 검색에 `market=from_token`을 쓰면 **403 Insufficient client scope**가 난다(추가 scope가 필요한 것으로 추정). → `market=KR`처럼 **국가 코드를 명시**한다. 국가는 설정에서 고를 수 있게 한다.

## R5. 검색

- `limit` 최대 10, 11 이상은 400.
- 검색 결과의 **track에는 `external_ids.isrc`가 있다** → 곡 매칭에 ISRC를 쓸 수 있다.
- 검색 결과의 **album에는 `external_ids`(UPC)가 없다.** `GET /albums/{id}`로 개별 조회해야 하며, 배치 조회(`GET /albums`)는 폐지됐다. → 앨범 매칭은 이름/아티스트/연도/트랙 수 기반으로 하고, UPC는 쓰지 않는다.
- album 객체에서 `label`, `popularity`가 사라졌다. `release_date`, `total_tracks`는 남아 있다.

## R3. YT Music 보관함 읽기

브라우저 헤더 인증(`ytmusicapi` 1.12.3), `limit=None`으로 전체 조회:

| 항목 | 개수 | 소요 |
|---|---|---|
| 보관함 앨범 | 218 | 3.5s |
| 구독 아티스트 | 8 | 0.3s |
| 좋아요 곡 | 1,298 (고유 1,250, 중복 48) | 10.9s |

- **불일치:** 좋아요 플레이리스트의 `trackCount`는 **1,533**인데 실제로 받은 곡은 1,298이다(235개 차이). 원인 후보:
  1. 삭제되거나 비공개된 영상이 개수에는 포함되지만 목록에서는 빠진다.
  2. 페이지네이션이 중간에 끊긴다.
  - **조사 결과:** 요청을 추적하니 100곡 × 12페이지 + 98곡에서 서버가 continuation 없이 정상 종료했고, 재조회해도 결과가 같았다. 사용자 앱 표시도 1,533. → 원인은 1번(삭제·비공개·지역 차단 영상)으로 판단한다. 이 곡들은 메타데이터가 없어 이전할 수 없다.
  - **제품 반영:** 결과 화면에 "YT Music에서 사용할 수 없는 곡 N개는 제외됨"을 표시한다(N = trackCount − 실제 수신 수).
- 구독 아티스트 8명과 앨범 218개(정규 148 / EP 34 / 싱글 36)는 사용자 확인으로 일치한다. 이 사용자는 앨범 위주로 저장하고 구독은 거의 하지 않는다.
- 같은 영상이 **중복**으로 들어 있다(48개). → 제품에서는 `videoId` 기준으로 중복을 제거한다.
- 조회 속도는 문제없다(전체 15초 안팎).

## R4. 좋아요 곡 구성과 UGC

| videoType | 개수 | 비율 |
|---|---|---|
| ATV (정식 음원) | 929 | 72% |
| **UGC (사용자 업로드)** | **334** | **26%** |
| OMV (공식 MV) | 18 | 1% |
| OFFICIAL_SOURCE_MUSIC | 13 | 1% |
| 없음 | 4 | 0% |

- 정식 음원(ATV) 928곡에 앨범 정보가 있다 → 앨범명까지 써서 정확하게 매칭할 수 있다.

**UGC 제목 키워드로 대략 분류한 결과 (334개):**

| 분류 | 비율 | 예시 |
|---|---|---|
| 라이브/무대/방송 클립 | 23% | 온스테이지, 쇼미더머니 본선, 콘서트 |
| 모음/믹스/풀앨범 | 18% | "한국힙합 TOP300", DJ 믹스, Full Album |
| 커버 / AI 커버 | 9% | "(AI Cover)", "(cover by …)" |
| 리믹스 | 5% | "(ANIME REMIX)", "(House Remix)" |
| 원곡 재업로드로 추정 | 6% | "(Official HD Music Video)", "(1995)" |
| 분류 불가 | 39% | 공백뿐인 제목, 밈, 서브컬처 곡 등 |

**UGC 샘플 30개를 단순 검색으로 매칭한 결과** ("아티스트 - 제목"으로 파싱한 뒤 Spotify 트랙 검색):

- 점수 0.75 이상: 7/30. 그런데 그중 **절반 이상은 변형곡을 원곡에 잘못 매칭한 것(오탐)**이다.
  - "Post Malone - Circles (**cover by** …)" → 원곡 Circles (1.00)
  - "JENNIE - MANTRA (**CRAZY ver.**)" → 원곡 Mantra (1.00)
  - "LNGSHOT – Moonwalkin' (**ANIME REMIX**)" → 원곡 (1.00)
  - → 괄호를 먼저 지우고 비교하면 변형 정보가 사라진다. **변형 감지는 원본 제목으로 먼저 해야 한다.**
- **한글/영문 표기 차이로 놓친 경우(미탐)**가 많다:
  - "서울전자음악단" vs "서울 전자 음악단" → 공백 차이
  - "구남과여라이딩스텔라" vs "Goonamguayeoridingstella", "백현진" vs "Bek Hyunjin", "최엘비(CHOILB)" → 로마자 표기
  - "희대의 (HEEDAE)"처럼 괄호 안의 별칭
  - → 공백을 무시하고 비교하며, "한글 (English)" 형태의 이름은 **양쪽 표기를 모두 후보로** 쓴다.
- 대략적인 추정: UGC 중 **정확히 같은 원곡은 10~15%**, **대체곡 후보 40% 내외**, **Spotify에 없는 곡 약 45%**.

**제품 결정:**
1. 좋아요 곡은 videoType으로 경로를 나눈다. ATV/OMV는 일반 매칭(ISRC는 YTM에서 얻을 수 없으므로 제목+아티스트+앨범으로 매칭), UGC는 별도 처리한다.
2. UGC는 **자동 체크를 하지 않는다.** 정확히 일치해도 사람이 확인하게 한다(오탐 위험).
3. 변형 키워드(cover, remix, live, ver., 무대, 직캠 등)가 있으면 "대체곡"으로 표시한다.
4. 이전되지 않는 UGC가 140개 이상 나올 것으로 예상된다 → **보존 기능(F11/F12)은 P0로 다뤄야 한다.** F12(YT Music 플레이리스트 생성)를 P1에서 P0로 올리는 것을 검토한다.
5. 매칭 품질 평가용 **정답셋**을 이 데이터로 만든다(F16).

## 결론

| 결정 | 근거 |
|---|---|
| 프로젝트 진행: **Go** | 차단 리스크(R0, R1, R2) 모두 해소. R0은 우회 방법이 있다. |
| Spotify 쓰기는 `PUT /me/library?uris=` (쿼리스트링, 40개씩) | R1 |
| 검색은 `market`을 명시한다(설정값, 기본 KR) | R2 함정 |
| 좋아요 곡은 videoType으로 경로를 나누고, UGC는 자동 체크하지 않는다 | R4 |
| 미이전 항목 보존(F11, F12)을 P0로 올린다 | R4: UGC 중 약 45%는 Spotify에 없음 |
| 매칭 정답셋은 이번 실제 데이터로 만든다 | R4 |
