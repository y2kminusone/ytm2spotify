# ADR-006: 프로젝트를 중단한다

- 상태: Accepted
- 날짜: 2026-10-13
- 대체: [ADR-005](005-auto-resume-while-running.md) (구현하지 않음)

## 맥락

v0.0.1로 앨범 208개, 아티스트 6명, 좋아요 곡 177곡을 Spotify에 옮겼다. 남은 좋아요 약 1,034곡은 Spotify 검색 할당량(R6) 때문에 2~3일에 걸쳐 매칭해야 했다. 이를 위해 자동 재개(ADR-005)와 매칭 화면을 다음 작업으로 잡아 두었다.

그 사이 사용자가 남은 이전을 **TuneMyMusic으로 모두 끝냈다.** 직접 써 보니 이 도구가 TuneMyMusic보다 나은 점을 찾을 수 없었다.

## 다시 따져 본 차별점

| PRD에서 내세운 점 | 실제 |
|---|---|
| 기존 SaaS는 대량 이전이 유료다 | 일회성 이전이라 한 달 결제 후 해지하면 된다. 우리 도구도 할당량 때문에 2~3일이 걸린다 |
| 매칭 결과를 이전 전에 검토할 수 있다 | 앨범 자동 매칭이 94%였고, "확인 필요" 6개도 모두 맞는 매칭이었다. 검토 화면의 가치가 예상보다 작다 |
| 앨범·아티스트·좋아요 곡까지 옮긴다 | 경쟁 제품도 옮긴다 |
| 로컬 실행이라 계정 정보가 PC 밖으로 나가지 않는다 | 이것 때문에 도구를 고를 사용자는 소수다 |
| 장기적으로 양방향 자동 동기화 (ROADMAP v0.4) | 먼 미래의 일이고, 아래 진입 장벽은 그대로 남는다 |

**진입 장벽은 구조적인 문제라 해결할 수 없다.** Spotify Development 모드는 앱당 사용자 5명으로 제한된다. 그래서 사용자마다 Premium 계정으로 개발자 앱을 직접 만들어야 하고(R0), YT Music 쿠키도 붙여넣어야 한다. 쿠키는 몇 시간 만에 만료되기도 했다. 클릭 몇 번이면 연결되는 웹 서비스와 경쟁할 수 없다.

## 결정

개발을 **중단**한다. 코드와 문서는 그대로 보관하고, 남은 작업(자동 재개, 매칭 화면, 설정 마법사, 배포)은 하지 않는다.

## 결과

- (+) 사용자에게 가치가 없는 기능에 시간을 더 쓰지 않는다.
- (+) 지금까지의 결정 과정과 실사용 기록은 그대로 남는다. 중단 이유는 [회고](../RETROSPECTIVE.md)에 정리한다.
- (−) 여기서 얻은 Spotify API 동작 확인 결과(R1, R2, R5, R6)와 한글/로마자 매칭 로직은 다른 곳에 쓰지 않는 한 묻힌다.
