# ADR-002: 상태 저장소로 SQLite를 사용한다

- 상태: Accepted
- 날짜: 2026-10-12

## 맥락

양쪽 보관함 스냅샷, 매칭 결과, 사용자 검토 결정, 적용 진행 상황을 저장해야 한다. 요구사항:

- 항목 1,500개 이상 (본인 데이터: 앨범 218, 좋아요 곡 1,298)
- 적용 중 끊겨도 이어서 할 수 있어야 한다 (PRD F9)
- 다시 실행하면 이전 결정을 유지하고 새 항목만 추가한다 (DESIGN §3.1)
- "검토 필요만 보기" 같은 상태별 조회
- 비개발자가 설치 없이 실행 파일로 쓴다

## 검토한 대안

| | SQLite | JSON 파일 |
|---|---|---|
| 상태별 조회 | SQL | 전체 로드 후 필터 |
| 부분 갱신 / 중단 안전성 | 트랜잭션, 행 단위 | 매번 파일 전체 재작성 |
| 설치 | Python 표준 라이브러리, PyInstaller 자동 포함 | 동일 |
| 직접 열람 | DB 뷰어 필요 | 텍스트 편집기 |

## 결정

SQLite(`sqlite3` 표준 라이브러리)를 쓴다. ORM 없이 얇은 저장소 계층(repository)을 직접 작성한다.

## 결과

- (+) 추가 의존성과 설치가 없다. 사용자는 DB의 존재를 몰라도 된다.
- (+) 적용 단계에서 항목 단위로 커밋해 중단 후 재개가 안전하다.
- (−) 사용자가 데이터를 직접 보기 어렵다. → UI에 CSV/JSON 내보내기를 제공한다 (F11).
- (−) 스키마가 바뀌면 마이그레이션이 필요하다. → `meta.schema_version`으로 관리한다.
